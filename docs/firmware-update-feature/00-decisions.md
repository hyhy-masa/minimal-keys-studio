# Track2 有線ファーム更新 — 決定事項ログ

まさかず判断（2026-07-09）。詳細設計は 03-design-fable5.md。

## 確定した方針
- **案A（Studioネイティブ統合）で進める**。ただし「実装の現実性・完成度」に疑問あり → 着手時に**実現性スパイクで検証してから本実装**する（特に下記の設定バックアップ/復元）。
- **実装はブランチ＋git worktreeで行う**（mainを汚さない）。

## 決定1: settings_reset（GATT変更更新）での顧客設定消失への対処
- **選択 = (a) バックアップ→復元機構を入れる**（設計のM5に追加）。
- **ただし懸念**: 実装の現実性・完成度に疑問。→ 本実装前に「Studioの各カスタムRPC（keymap/combos/trackball/hold-tap 等）で**設定の読み出し(get)と書き戻し(set)が両方できるか**」を実機スパイクで確認する。全設定を読めて戻せるなら(a)は成立、無理な項目があれば範囲を明示して割り切る。
- BLEボンドは対象外（復元不可・再ペアリング案内で対応）。

## 決定2: 顧客への更新案内チャネル
- **公式LINE または Discord で案内**する。
- → アプリ内の `min_studio_version` ゲートに頼り切らず、LINE/Discordで「先にStudioを更新してください」と人手で誘導できる。署名の優先度もこの前提で判断。

## 決定3: 実装着手
- **着手可**。ただし branch + worktree で作業。
- 順序: Codexレビュー反映 → worktree作成 → M0（配布パイプライン）→ M1（Rust書込コア）→ M2（Mac UI＝MVP）。M5（settings_resetフロー＋(a)の復元）は決定1のスパイク結果を見てから。

## 未反映・保留
- Codex独立レビュー（第3の目）結果 → 反映予定。
